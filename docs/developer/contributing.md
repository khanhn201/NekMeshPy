# Contributing

## Development setup

```bash
pip install -e ".[all,dev]"    # numpy, scipy, matplotlib, meshio, ruff, mypy, pytest
```

## The three checks

CI (`.github/workflows/ci.yml`) runs ruff + mypy on Python 3.12 and pytest on
3.9–3.12. **All three must stay green.**

```bash
ruff check nekmeshpy tests examples          # lint
mypy                                         # type-check (config pins files=["nekmeshpy"]; do NOT pass paths)
MPLBACKEND=Agg python -m pytest              # full suite (Agg needed: viz tests import matplotlib headless)
```

Run a single test or subset:

```bash
pytest tests/test_api.py::test_to_mesh_groups   # one test
pytest -k re2                                    # by keyword
```

The whole `nekmeshpy` package is fully annotated and checked with
`disallow_untyped_defs` **and** `disallow_any_generics` — see {doc}`conventions`
for the typing rules array code must follow.

## The golden-regression invariant

**Read this before editing anything numeric.** `tests/` freezes the output of
`examples/bifurcation.py` in `tests/golden/` and asserts it **byte-for-byte**: the
`.rea` and the `.re2` boundary block are byte-exact, `.re2` coordinates match to
`1e-12`, and `.vtk` is byte-identical. The numerics were ported verbatim from a
reference MATLAB/Octave implementation, so "results unchanged" is a hard
constraint — most refactors here are expected to be output-preserving.

After any change that could touch geometry/numerics, verify:

```bash
cd /tmp && PYTHONPATH=<repo> MPLBACKEND=Agg python <repo>/examples/bifurcation.py
for f in bifurcation.re2 bifurcation.rea bifurcation.vtk; do
  cmp -s "$f" "<repo>/tests/golden/$f" && echo "$f OK"
done
```

The pipe and external-flow examples have **no** goldens (tolerance-only quality
tests), so they may change; the bifurcation must not. When a change is meant to be
pure (rename, restructure), treat a golden diff as a bug.

If you *intentionally* change the bifurcation configuration, the golden files **and**
the derived counts asserted in `tests/test_regression.py` / `tests/test_api.py`
must be re-frozen together, in one consistent snapshot.

## Examples are integration tests

Concrete meshers live in `examples/` as flat gmsh-style scripts that assign a
`mesh` global and export. The suite runs them via `runpy.run_path`
(`tests/conftest.py`) and inspects that global, so an example must always keep
producing a valid `mesh`. When you add a geometry, add its script here.

## Documentation

The docs are Sphinx + MyST (this site). Build locally:

```bash
pip install -e ".[docs]"
MPLBACKEND=Agg sphinx-build -b html -n --keep-going docs docs/_build/html
```

`.github/workflows/docs.yml` builds the docs on every PR and deploys them to
GitHub Pages on `main`. The API reference is generated by `autosummary` from
docstrings, so **new public symbols need a docstring** — coverage is expected to
stay at 100%.
